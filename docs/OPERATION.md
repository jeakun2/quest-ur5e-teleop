# 조작 가이드

## 1. 기본 조작 (헤드셋을 벗어도 됨)

| 입력 | 동작 |
|---|---|
| **그립**(중지 버튼) 쥔 채 움직이기 | 로봇 TCP가 컨트롤러의 **위치(xyz)와 회전**을 그대로 따라온다 |
| 그립 놓기 | 로봇이 그 자리에 멈춘다. 손을 편한 곳으로 옮겨 다시 쥐면 거기서 이어서(래칫) |
| **트리거**(검지) | 그리퍼 (아날로그 0..1) |
| **A** | 옵션 메뉴 열기 (메뉴 안에서는 선택). 회전 추종 켜기/끄기는 메뉴 항목 |
| **B** | 누르는 동안 즉시 정지(servoStop) |
| **썸스틱 클릭** | 메뉴 열기/닫기 (A와 같음. 헤드셋 착용 시에만) |

### 헤드셋을 벗고 쓰기(헤드리스)

Quest는 얼굴이 떨어지면 몇 초 뒤 잠들고 트래킹도 멈춘다. 둘 중 하나로 깨어 있게 한다.

1. **개발자 모드 + USB(adb)**: `python tools/quest_keep_awake.py on` (끝나면 `off`).
   `--source.type oculus_reader`는 `keep_awake: true`(기본)로 시작할 때 자동으로 보낸다.
2. 개발자 모드 없이: **근접 센서를 테이프로 가린다**(렌즈 사이, 코 받침 위의 작은 창).

헤드셋은 **컨트롤러가 보이도록**(카메라가 작업 공간을 향하게) 올려둔다. Quest 3 컨트롤러는 헤드셋 카메라로
추적되므로 시야 밖으로 나가면 `tracked=false`가 되고 브리지가 클러치를 푼다.

브리지는 머리 포즈가 3초간 정지(`ui.head_still_s`)하면 **headless** 모드로 판단해 메뉴를 잠근다(오조작 방지).
헤드리스 상태에서 축 고정·녹화·배율 등을 바꾸려면 PC에서 **`https://<PC IP>:8765/monitor.html`**을 연다.
모드는 `--ui.mode headless|hmd|auto`로 고정할 수도 있다.

## 2. 헤드셋 착용 시: 메뉴

**A**(또는 썸스틱 클릭) → 옵션 메뉴(스틱 위/아래 이동, A 선택, B 닫기). 메뉴가 열려 있는 동안 로봇은 정지한다.

| 항목 | 내용 |
|---|---|
| 초기 자세로 | 브리지를 켰을 때의 TCP로 속도 제한 안에서 되돌아간다(그리퍼 열림). B로 중단 |
| 회전 추종 | 켜짐/꺼짐 (꺼지면 위치만 따라옴) |
| Isaac 씬 초기화 | 시뮬레이션 물리 오류(관절 폭주·NaN)가 났을 때 씬 전체를 다시 초기화한다(홈 자세·그리퍼 열림·큐브 복귀). 발산은 시뮬이 자동 감지해 초기화하기도 한다 |
| 튜토리얼 | 6단계 안내. 실제로 그립·래칫·트리거·A·B·스틱을 써 보며 각 단계가 자동으로 넘어간다 |
| 보정 (로봇 방향·조작 위치) | ① 그립 쥔 채 로봇 쪽으로 20 cm 밀기 → `operator_yaw_deg` ② 편한 조작 중심에서 트리거 → `center_xr`,`tcp_center` ③ 확인: 그립 쥐고 로봇 쪽 10 cm → 로봇이 +X로 갔는지 자동 판정(오차 20° 이내) ④ A = `config.yaml` 저장 |
| 정밀 보정 (3축 제스처) | 로봇 +X, +Y, +Z 방향으로 30 cm씩 → `r_map` 전체를 SVD로 구해 저장 (`calibrate_frame.py`와 같은 계산) |
| X/Y/Z축 고정, 회전 고정 | 고정된 축은 클러치를 쥔 시점의 값에 머문다. 예: Z 고정 → 평면 작업, 회전 고정 → 자세 유지 |
| 녹화 시작/정지 | `runs/rec_YYYYmmdd_HHMMSS.jsonl`에 컨트롤러 샘플 + 로봇 TCP + 그리퍼 명령을 매 프레임 저장 |
| 마지막 녹화 재생 | 현재 위치에서 속도 제한 안에서 첫 포즈로 접근한 뒤 녹화 속도대로 TCP 궤적을 재생. **B로 즉시 중단** |
| 이동 배율 | x0.25 / 0.5 / 1 / 1.5 |
| 매핑 방식 | 상대(래칫, 기본) / 절대(보정한 중심 기준으로 손 위치 = 로봇 위치, 반복 작업에 유리) |
| 천장/사이드/EE 카메라 오버레이 | Isaac 창 모드에서 가상 카메라 3대(천장 위에서, 옆에서, 그리퍼 옆에서 손끝 방향)의 영상을 헤드셋 오른쪽에 2D로 띄운다(320×240, 8 Hz). 켜져 있는 카메라만 렌더한다 |
| Isaac 시점 전환 | Isaac 창의 뷰포트 카메라를 default → top → side → ee(손끝 따라감) 순으로 바꾼다 |
| 홀로그램 손에 맞추기 | 다음에 그립을 쥐는 순간 AR의 반투명 UR5e 툴이 손 위치에 오도록 홀로그램을 다시 놓는다 |
| 홀로그램 옮기기/돌리기 | 그립을 쥔 채 손을 옮기면 홀로그램(로봇 초기 위치)이 따라오고, 손목을 좌우로 돌리면 손을 축으로 회전한다. A 또는 B로 완료. 완료 시 조작 yaw(`operator_yaw_deg`)가 홀로그램 방향에 맞게 갱신돼 "홀로그램 +X = 손 앞" 관계가 유지된다 |
| 경로 지우기 | AR에 그려진 TCP 경로(하늘색)·손 경로(주황)를 지운다 |

보정 결과는 `bridge/config.yaml`의 `mapping:`에 기록되므로 다음 실행부터 자동 적용된다.

표시·명령에 쓰는 **EE 좌표는 TCP**(그리퍼 손끝 중심)다. Isaac 2F-85는 플랜지에서 0.121 m, 실기는 PolyScope의 TCP 설정을 따른다.

## 2-1. AR 홀로그램과 경로 (헤드셋 착용, Start AR/VR)

- 처음 그립을 쥐면 **반투명 UR5e**가 나타난다. 툴(플랜지 좌표축)이 그 순간의 손 위치에 놓이고, 이후에는 브리지가 보내는
  **실제 관절 각도**(Isaac Sim·실기 ur_rtde)로 움직인다. 더미 로봇은 관절값이 없어 툴 좌표축과 그리퍼만 보인다.
- 로봇 방향은 보정값(`operator_yaw_deg`, `r_map`)을 그대로 따르므로, 보정이 맞으면 홀로그램의 +X가 실제 로봇의 +X와 같은 쪽이다.
- 그리퍼(트리거)는 홀로그램 손가락 간격으로 표시된다.
- **경로**: 그립을 쥐고 움직이는 동안 TCP 경로(하늘색, 15 Hz 상태값)와 손 경로(주황, 프레임마다)가 선으로 남는다.
  재생 중에도 TCP 경로가 그려진다. 메뉴 "경로 지우기" 또는 모니터 페이지에서 지운다.
- 홀로그램은 이동 배율을 반영하지 않는다(실제 로봇 기하 그대로). 배율 0.5면 손 10 cm에 홀로그램 툴 5 cm가 움직이므로
  어긋나면 "홀로그램 손에 맞추기"로 다시 정렬한다.

## 3. 좌표계

- 기본 `r_map`: 조작자가 로봇 베이스 뒤에서 로봇 +X를 바라본다고 가정(앞으로 밀기 = +X, 왼쪽 = +Y, 위 = +Z).
- 다른 자리에 서면 메뉴의 "보정" 1단계만으로 yaw가 맞춰진다. 바닥이 기울었거나 정밀하게 맞추려면 "정밀 보정".
- 회전: 컨트롤러의 상대 회전이 같은 축으로 TCP에 적용된다(손목을 돌리면 툴이 돈다).

## 4. 안전

- 클러치 해제, 트래킹 끊김, 0.3 s 샘플 없음, 메뉴 열림, 보호정지/비상정지 → 즉시 `servoStop`.
- 주기당 이동량 `max_lin_speed` 0.25 m/s, `max_ang_speed` 1 rad/s. 재생도 같은 제한을 받는다.
- 작업공간 박스·반경 클램프. 처음에는 `--mapping.pos_scale 0.5 --robot.speed_slider 0.3`으로.
- 헤드리스로 쓸 때는 로봇이 **직접 보이는 자리**에서만 조작하고, 티치펜던트 비상정지를 손 닿는 곳에 둔다.

## 5. 시뮬레이터로 연습하기

- **URSim(도커)**: `tools\ursim_up.ps1` → `--robot.type ur_rtde --robot.ip 127.0.0.1`. 실제 컨트롤러 소프트웨어(PolyScope)라 가장 충실하다.
- **Isaac Sim 4.2**: `python tools\isaac_sim.py`(창 있음) 또는 `--headless` → `--robot.type isaac`. 물리·충돌이 있는 3D 장면에서
  같은 조작·메뉴·녹화를 그대로 쓸 수 있다. 자세한 것은 `docs/ISAAC_SIM.md`, Quest까지 포함한 순서는 `docs/GUIDE_QUEST_ISAAC.md`.
